# Передача работы следующей сессии

Зачем: 97 % расхода лимита — перечитывание длинного контекста (замер 24.09.2026: средний
запрос тянет 226 тыс. токенов). Свежая сессия, которая начинает с короткого файла
передачи, дешевле в разы и работает точнее.

## Шаги

1. Определи папку текущего проекта — ту, где идёт работа. Файл:
   `<папка проекта>\00 ПЕРЕДАЧА.md`. Если файл уже есть — перезапиши раздел «Сейчас» и
   допиши в «Историю» одну строку о прошлой передаче, старое не выбрасывай.
2. Запиши инструментом Write (не через bash):

```markdown
# Передача: <тема>
Обновлено: <дата, время>. Следующая сессия нужна для: <одна строка>.

## Сейчас
- Цель: <что в итоге должно получиться>
- Где остановились: <последний сделанный шаг>
- Следующий шаг: <конкретное действие, с которого начать>

## Сделано
- <что> → `<путь к файлу>`

## Решения и почему
- <решение> — <причина>; отвергнуто: <что и почему>

## Открытые вопросы
- <вопрос> — кто решает (пользователь / владельцы / проверить самому)

## Грабли
- <что уже ломалось и как обошли>

## Какие скиллы звать
- <имя скилла> — для чего

## История
- <дата>: <одна строка о прошлой передаче>
```

3. Не дублируй то, что уже лежит в файлах: ссылайся путём. Не пиши ключи, пароли,
   токены и номера карт.
4. Важные выводы, которые пригодятся не только в этом проекте, — в память
   (`MEMORY.md`), а не только в передачу.
5. Скажи пользователю одной строкой: «Передача в `<путь>`. Сделай `/clear` и напиши:
   продолжи по `<путь>`».

## Готово, когда

По файлу без текущего разговора понятно: что делаем, где остановились, какой следующий
шаг и где лежат результаты.
