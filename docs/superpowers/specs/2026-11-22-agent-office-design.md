# Офис агентов: дизайн

Дата: 2026-11-22. Внешний вид утверждён на макете «Офис Claude» (3D, четыре этажа).

## Зачем

Пользователь даёт Claude задачу и хочет видеть, что работа идёт: кто из
субагентов, скиллов и MCP-инструментов чем занят прямо сейчас. Идею он видел
в соцсетях и хочет такую же у себя.

## Цели

- Страница «Офис Claude» в браузере на компьютере пользователя (Windows). Это
  3D-здание из утверждённого макета: четыре этажа, стеклянный лифт по центру,
  круглый холл и коридор на каждом этаже, кабинет Claude наверху.
- Живые данные: реальные шаги главной сессии и каждого субагента с задержкой
  1–2 секунды.
- Панель задач и карточка агента со всеми его шагами, как в макете.
- Запуск двойным щелчком, без установки дополнительных программ.

## Не делаем

- Управление агентами из офиса (остановить, перезапустить).
- Облачные сессии (claude.ai/code). Только Claude Code на этом компьютере.
- Показ внутри Claude Code и на телефоне.
- Историю прошлых дней и повтор записи.

## Анти-цели (провал, даже если «работает»)

- Офис что-то меняет в Claude Code, его настройках или файлах. Он только читает.
- Офис доступен кому-то, кроме этого компьютера.
- Офис заметно тормозит Claude или компьютер.

## Подходы

1. **Чтение журналов (выбран).** Claude Code сам пишет каждый шаг в
   `~/.claude/projects/<проект>/<сессия>.jsonl`, а шаги каждого субагента в
   `<сессия>/subagents/agent-<id>.jsonl`. Маленький локальный сервер отдаёт
   странице новые строки этих файлов, страница сама их разбирает.
   Плюсы: ничего не надо настраивать в Claude Code, видно каждого субагента.
   Минусы: формат файлов внутренний, Anthropic может его изменить.
2. **Хуки Claude Code.** Claude Code при каждом шаге шлёт событие на сервер.
   Плюсы: мгновенно. Минусы: нужно править `settings.json`, а это нарушает
   анти-цель «ничего не менять». Кроме того, не во всех версиях хуки шагов
   говорят, какой это субагент.
3. **Панель внутри Claude Code** (как мод `live-diff`). Минус: в терминале
   3D не нарисовать.

Выбран подход 1. Решение моё (Claude), пользователь отдал выбор «как» мне.

Сервер существует в двух вариантах с одинаковым API:
- `server.ps1` на PowerShell. Он встроен в Windows, поэтому ставить ничего не
  нужно (Claude Code на Windows ставится без Node.js);
- `server.mjs` на Node.js для macOS и Linux и для автоматических проверок.

## Как устроено

Папка `office/` в репозитории:

| Файл | Что |
| --- | --- |
| `index.html` | 3D-офис из макета, панель задач, карточка агента, демо-режим |
| `feed.js` | Разбор строк журналов в состояние офиса. Без зависимостей, работает в браузере и в тестах Node |
| `server.ps1` | Сервер для Windows |
| `server.mjs` | Тот же сервер на Node |
| `start-office.cmd` | Двойной щелчок на Windows: запускает `server.ps1` и открывает браузер |

Тесты лежат в `tests/office/*.test.mjs` и запускаются через `node --test`.

### Сервер (оба варианта одинаковы)

- Слушает только `127.0.0.1`, порт 4545. Если он занят, берёт следующий
  свободный, до 4555.
- Проверяет заголовок `Host`: допустимы только `127.0.0.1:<порт>` и
  `localhost:<порт>`. Это защита от подмены DNS: чужой сайт в браузере не
  сможет прочитать журналы.
- Не отправляет CORS-заголовков.
- Корень журналов: `$CLAUDE_CONFIG_DIR/projects`, а если переменная не задана,
  то `~/.claude/projects`.
- `GET /` отдаёт `index.html`, `GET /feed.js` отдаёт файл разбора.
- `GET /api/sessions` отдаёт до 20 главных журналов, изменённых последними
  (`*/*.jsonl`). Для каждого: относительный путь, проект, время изменения,
  размер и список его файлов `subagents/agent-*.jsonl` с размерами.
- `GET /api/read?file=<относительный путь>&from=<байт>` отдаёт
  `{text, next}`: текст с этого байта, не больше 4 МБ, обрезанный по последнему
  переводу строки.
- Путь `file` должен быть относительным, без `..`, оканчиваться на `.jsonl` и
  после разрешения лежать внутри корня. Иначе ответ 400.
- Файлы открываются только на чтение, с разрешением совместного доступа, чтобы
  не мешать Claude писать в них.
- В `server.ps1` при старте открывается браузер; `server.mjs` только печатает
  адрес.

### Страница

- Раз в секунду страница опрашивает `/api/sessions` и следит за сессией,
  изменённой последней. В панели есть выпадающий список «Сессия», чтобы
  закрепить другую. Новые байты главного журнала и журналов субагентов
  дочитываются по смещению.
- Если журналов нет или в адресе есть `?demo`, проигрывается демо-сценарий из
  макета с плашкой «Демо».

### Как журнал превращается в офис

- **Главная сессия** — это «Я (Claude)», рабочее место в кабинете на 4 этаже.
- **Сообщение пользователя** (не результат инструмента и не служебное) —
  новая задача. Заголовок задачи — первая строка сообщения, до 60 символов. На
  ресепшне появляется листок, «Я» получаю статус «Читаю задачу».
- **Вызов `Agent` или `Task`** из главной сессии создаёт экземпляр субагента.
  Ключ экземпляра — id вызова. У «Я» статус «Поручаю <тип>: <описание>»,
  субагент идёт из зоны отдыха в свою комнату.
- **Связь с файлом субагента.** Файл `agent-<id>.jsonl` привязывается к вызову
  по тексту первого сообщения (это `prompt` вызова). Запасной путь: `agentId`
  из результата вызова.
- **Субагент закончил**, если пришёл результат его вызова без статуса
  `async_launched` или его журнал закончился ответом со `stop_reason:
  end_turn`. Тогда он возвращается в зону отдыха.
- **`Skill` у главной сессии** — «Я» иду к полке скиллов на 4 этаже. У
  субагента это только статус, он остаётся в своей комнате.
- **`mcp__<сервер>__<инструмент>`** — агент идёт на 1 этаж к стене экранов,
  загорается экран сервера. Экранов четыре, неизвестные сервисы занимают
  свободный экран по очереди, подпись — имя сервера.
- **Остальные инструменты** меняют только статус, агент остаётся на месте:
  - `Read` — «Читает <файл>»;
  - `Edit`, `Write`, `MultiEdit`, `NotebookEdit` — «Правит <файл>»;
  - `Bash` — описание вызова или начало команды;
  - `Grep`, `Glob` — «Ищет: <шаблон>»;
  - `WebSearch` — «Ищет в интернете: <запрос>»;
  - `WebFetch` — «Читает сайт <хост>»;
  - `TodoWrite`, `Task*` — «Обновляет план»;
  - прочие — имя инструмента.
- **Простой.** Если последний ответ главной сессии закончился `end_turn` и
  открытых вызовов нет, «Я» получаю статус «Жду задачу», а задача в панели
  отмечается выполненной.
- **Комнаты по типу агента:**
  - Библиотека (3 этаж): researcher, Explore, claude-code-guide, web-fetch;
  - Переговорная (2 этаж): critic, Plan;
  - Капсула проверки (3 этаж): reviewer, verifier;
  - Open space (2 этаж): developer, debugger, mod-builder, general-purpose и
    все остальные типы.
- **Персонажи.**
  - Постоянный состав — десять известных типов из макета, свободные стоят в
    зоне отдыха.
  - Второй одновременный экземпляр того же типа приезжает на лифте как копия
    с подписью «#2» и уезжает, когда закончит.
  - Неизвестный тип (например, нанятый через `hire-agent`) получает
    персонажа с цветом из хеша имени.
- **Карточка агента** показывает реальные шаги этого экземпляра со временем.

## Ограничения, о которых знаем

- Нужна версия Claude Code, которая пишет папку `subagents/`. Старый формат,
  где шаги субагентов лежали внутри главного журнала, не поддерживаем.
- Three.js грузится с jsdelivr, поэтому для 3D нужен интернет.
- `server.ps1` проверяется здесь на PowerShell 7 под Linux. Windows PowerShell
  5.1 на настоящем Windows здесь проверить нельзя: первый запуск у
  пользователя станет проверкой.
